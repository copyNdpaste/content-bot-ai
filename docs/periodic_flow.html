과거 기록만 있음

전체 흐름

1
launchd 부팅 com.contentbot.content-scheduler가 RunAtLoad/KeepAlive로 실행됩니다.
2
운영 시간 체크 KST 09:00-23:00 안에서만 회차를 시작합니다.
3
랜덤 간격 기본 2-3시간 랜덤 대기, 최소 2시간 보호가 적용됩니다.
4
Pack 생성 scripts/generate_platform_pack.py가 계정별 글과 이미지를 만듭니다.
5
Slack 및 업로드 Slack에 카드가 올라가고 Instagram/Threads는 자동 업로드됩니다.
6
큐 재시도 쿨다운 draft는 5분마다 queued_upload_worker가 다시 시도합니다.

주기 실행 타임라인

부팅 또는 재시작
scheduler.py 시작

plist: launchd/com.contentbot.content-scheduler.plist
실행 파일: .venv/bin/python3 src/workflow/scheduler.py
로그: /tmp/contentbot-content-scheduler.log, /tmp/contentbot-content-scheduler.err

매 루프
활성 시간과 최소 간격 확인

ROUTINE_ACTIVE_START_HOUR=9, ROUTINE_ACTIVE_END_HOUR=23. 이전 회차 시작 시간이 var/content-scheduler-state.json에 저장되고, 최소 2시간이 지나야 다음 회차를 허용합니다.

회차 시작
generate_platform_pack.py 호출

스케줄러는 --platforms ROUTINE_PLATFORMS, --accounts ROUTINE_ACCOUNTS로 pack generator를 실행합니다. 현재 값은 실제 로딩 기준으로 platforms=threads,instagram,x, accounts=jp,kr입니다.

회차 종료 후
다음 랜덤 간격 계산

기본 ROUTINE_MIN_HOURS=2, ROUTINE_MAX_HOURS=3 범위에서 매번 새 간격을 뽑습니다. 다음 시간이 운영 시간 밖이면 다음 09:00 KST까지 대기합니다.

한 회차 내부

계정별 pack 생성

  • kr, jp 계정을 순회합니다.
  • ROUTINE_DISABLED_TARGETS에 걸린 플랫폼/계정은 제외합니다.
  • Google Trends RSS와 Supabase 또는 config/content_styles.json 스타일 컨텍스트를 읽습니다.
  • Instagram 기준 글을 Codex CLI로 만들고, 실패 시 설정에 따라 Claude CLI로 폴백합니다.

플랫폼별 변환

  • Instagram 글을 기준으로 Threads와 X 문구를 같은 감정선으로 변환합니다.
  • 필수 CTA와 글자 수 제한은 코드에서 다시 보정합니다.
  • Threads는 500자, X는 280자, Instagram은 2200자 제한을 적용합니다.

이미지 생성

  • 회차별 공유 이미지 1장을 만듭니다.
  • _call_codex_image_prompt가 본문을 읽어 GPT 이미지용 영문 프롬프트를 만듭니다.
  • CODEX_IMAGE_COMMAND가 로컬 PNG를 생성합니다.
  • IMAGE_PUBLIC_URL_COMMAND가 Meta API에 넘길 공개 HTTPS URL을 만듭니다.

저장, 알림, 업로드

  • 각 플랫폼 draft가 drafts/{platform}-{timestamp}-{account}.md로 저장됩니다.
  • Slack에 본문과 이미지 미리보기가 올라갑니다.
  • Instagram/Threads는 Slack 알림 뒤 바로 자동 업로드됩니다.
  • X는 API 비용 이슈 때문에 수동 업로드 모드입니다.

현재 설정 스냅샷

항목 현재 값 의미
대상 플랫폼 threads,instagram,x 회차마다 세 플랫폼 draft를 생성합니다.
대상 계정 jp,kr JP/KR 두 계정을 순회합니다.
비활성 타겟 instagram:jp JP Instagram은 자동 회차에서 제외됩니다. JP Threads는 제외되어 있지 않습니다.
이미지 대상 instagram,threads,x 세 플랫폼 모두 이미지 생성 대상으로 설정되어 있습니다.
마지막 회차 시작 2026-06-08T13:20:07 KST var/content-scheduler-state.json 기준입니다.

자동 업로드와 큐

성공 경로

  • Threads: threads_uploader.py --text ... --account jp|kr --image-url ...
  • Instagram: instagram_uploader.py --caption ... --account jp|kr --image-url ...
  • 업로더는 src/auth/tokens.json에서 계정별 access token과 user id를 읽습니다.
  • 만료 임박이면 token_manager.py --refresh를 한 번 시도합니다.

실패 및 재시도 경로

  • Instagram 행동 제한이 감지되면 .runtime/instagram_cooldowns.json에 계정별 until을 저장합니다.
  • 업로더 stderr에 COOLDOWN_UNTIL=...이 있으면 draft 상태가 queued로 바뀝니다.
  • queued_upload_worker.py --interval 300이 5분마다 due draft를 다시 업로드합니다.
  • ROUTINE_DISABLED_TARGETS에 걸린 타겟은 큐 워커도 스킵합니다.
JP Instagram이 안 올라가는 가장 직접적인 이유 현재 설정에 instagram:jp가 비활성 타겟으로 들어가 있습니다. 다시 자동 회차에 포함하려면 .env의 ROUTINE_DISABLED_TARGETS에서 해당 항목을 제거하고 launchd 데몬을 재시작해야 합니다.
